# 瑾瑜记忆：旧核心 vs 新核心 A/B 测评（2026-10-29）

## 结论先行

- **新核心明显优于旧核心**：同一批 100 条真实问答、同一份快照，标准答案卡的原文进入最终 prompt 的比例 **57.0% → 85.0%**（+28.0 个百分点），McNemar 精确检验 p < 1e-5。
- 代价是上下文变大：平均注入卡 9.1 → 16.7 张，prompt 1834 → 2495 字符。
- 消融显示新核心的增益主要来自 **向量融合 + 召回上限 4 + 向量不挤掉字面命中**；证据闸门与显著性在本语料上没有可测增益；时钟短路、四级披露、细粒度 FUSE 各有明确用途（见消融表）。
- 紧预算（max_tokens=3600、可用约 3.1k）下新核心自身从 85.0% 掉到 60.0%，仍高于旧核心 53.0%（+7.0 个百分点，但 4/11 对不显著）。真正兜住新核心的是细粒度 FUSE：没有它只有 25.0%，有它 60.0%（+35.0 个百分点，p < 1e-8）。

## 测评口径

- 数据：旧评测工程快照 `memory_eval/data/snapshot.db`（157 张事件卡、4 个会话、`vectors` 表 157 行 bge-m3 向量）。
- 问答：`memory_eval/data/qa.jsonl` 100 条真实探针（86 条原话复述 + 14 条纯钩子），每条都有唯一标准答案卡。
- 场景：把问题放在会话末尾（`upto=max_turn`），用两套核心各自构建完整 prompt，再在末尾追加当前用户消息；不调用前台/后台模型，纯确定性。
- 指标：`text` = 标准答案卡的摘要原文（前 40 字）真的出现在最终 system prompt 里（裁剪之后）；`full` = 裁剪前进入过全文通道；`low` = 标准答案卡被四级披露降为 paraphrase/hint；`silence` = 被静音；`inject` = 裁剪后仍可见的原文卡数；`secret_full` = 含保密词的卡以原文注入数。
- 显著性：配对 McNemar 精确检验（报告不一致对数 b/c）+ 2000 次配对 bootstrap 的 95% 百分位区间；比例另给 Wilson 区间。
- 核心：旧 `/tmp/memory_eval/core`（无 gate/disclosure/FUSE 细粒度，recall_limit=2）；新 `/opt/qqbot/bot/src/plugins/jinyu_memory/core`（recall_limit=4）。嵌入模型 BAAI/bge-m3。

## 逐机制解读

- **向量融合（最大贡献）**：关掉后 0.460（-0.390）。检索层向量 R@4 = 0.800、钩子只有 0.340；没有向量，复述类问句大量漏召回。
- **召回上限 4**：降到 2 后 0.810（-0.040，仅 4 题差异、p≈0.13，方向性而非定论）。旧核心即使检索到第 3/4 张，也因 limit=2 丢在门外。
- **四级披露**：关掉披露后 GT 反而多 0.010（仅 1 题，不显著），但含保密词的卡原文注入从 0.48 张/题降到 0.12，另有 0.52 张/题被降为 paraphrase/hint。这是用 1 个百分点的召回换 75% 的保密卡原文泄漏下降，方向正确；专项语料（`docs/disclosure-corpus-2026-10-29.md`）里 45/45 敏感题零原文泄漏、普通卡 15/15 未误伤。
- **细粒度 FUSE**：宽松预算下与整段注入无差异；紧预算（3.1k）下 0.250 → 0.600（+0.350），召回通道可见卡 1.5 → 4.1。整段注入一旦被裁剪就全丢，逐张成段能保住 top-1。
- **时钟短路**：16 条时间问句，旧核心平均召回 1.50 张（75% 的问句拉进了旧事），新核心 0.00 张、100% 不拉旧事；关掉短路后 3.88 张。这是零成本、零召回损失的纯收益。
- **证据闸门**：本语料 100 条问句的钩子最高分都远高于闸门线，闸门一刀没切；因此 prompt 级指标完全不变。它的价值在低证据问句（全是弱命中时不再硬凑 top-N），这批探针覆盖不到，不能据此否定，也不能据此声称有效。
- **显著性**：本语料 top 分几乎不并列，显著性开关对结果无影响；它只在同分竞争时改变排序，属于防御性机制。

## 2026-10-29 复核：主人私聊信任场景

产品策略变更：**已验证主人的私聊是信任场景**（`trusted = scene.is_private and scene.is_owner`），
`disclosure.exposure` 不再乘 boundary 与敏感度，只保留相关度；群聊 / 直播 / 未绑定私聊不变。

- 实测（60 条专项探针，`new_owner` 配置)：私聊四类卡 **20/20 原文**，其中敏感 15/15；
  群聊 + 直播的 30 条敏感探针仍 **0 原文**。全量原文可见率 0.250 → 0.500，
  低等级 0.500 → 0.333，静音 0.250 → 0.167。详见 `docs/disclosure-corpus-2026-10-29.md`。
- 跨会话通道同步改动：`cross_cards` 逐张校验 `audience`，`self` 卡只对已验证主人私聊跨界
  （`trusted=True`），其余场合不继承；回归 `R51` 覆盖群聊读私聊卡、非主人私聊读他人卡、主人私聊 self 跨界三种情形。
- 线上生效前提是 `owners.db` 里有 `status='verified'` 的绑定。本次已为 `qq:10001`
  （即 `RP_ADMIN_QQ`）写入 verified，重启后日志不再出现「主体解析失败」。
- 同时修掉一个潜伏 bug：`_principal_scope` 调用了不存在的 `_lane_base`，异常被
  `rp_skeleton._scope` 的 try/except 吞掉 → **主体合并与主人判定一直静默失效**；
  已改为 `rp_skeleton.lane_base`。

## 2026-10-29 复核：后台字段补全 + 前台自述

后台 AI 不再只写摘要，开始产出「这条记忆关于谁、是谁给的」：

- `summarizer` 的提示词新增 `subject`（卡的主体：主人 / 角色 / 钩子词）与
  `durable_facts[].speaker`；`validate` 只接受这两类可核验取值，代词与自造词一律丢弃
  （不猜，避免「他」落库后在跨会话里被当成某个具体的人）。
- `_archive_range` 把 `subject` 写进事件卡；事实的 `speaker` 经 `_fact_item`
  同时落到 `durable_facts.speaker` 与 `.subject`（两列同源，避免再分叉）。
- 前台新增【本轮记忆】：`近段对话 n 张、承诺卡 n 张、旧会话 n 张、检索命中 n 张（全文 x、模糊 y）`。
  前台由此知道「这轮到底翻到了什么」，不会再出现「明明有记忆却说没印象」，
  也不会把没给它的旧事当成已知。silence 的卡不计数（说「有 1 张被藏起来」本身也是信息）。
- 回归 `R52`（字段校验/落库/代词丢弃）、`R53`（前台自述）通过；披露语料指标不变
  （`full`/`text`/`low` 三列与改动前一致），prompt 每轮多约 90 字符。

接着把「后台产出」真正用起来，三步一起落地：

- **词条分面**：`list_facts_detail(..., speaker=当前说话人)`，关于眼前这个人的事实乘以
  `SPEAKER_BIAS=1.3` 排在别人同分事实前面；不传 speaker 时排序与改动前完全一致（`R54`）。
- **说话人透传**：`chat()` / `_build_messages()` 新增 `speaker` 参数，主对话、戳一戳、B 站弹幕
  三处调用点把群名片/昵称传下去；`disclosure._same_person` 改成「都能对得上就成立」的包含判断
  （`小明` 与 `小明(12345)` 算同一人），单字名不做包含以免误判。群聊里「关于他自己的
  self+保密卡」因此从 silence 升到 hint（`R55`）。
- **存量 audience 回填**：`_migrate` 启动时用写入时的同一函数 `default_audience` 补齐空 audience
  （线上覆盖 9 个会话的事件卡、6 个会话的事实）。空串在 `audience_ok` 里是「老数据放行」，
  不回填等于跨受众校验对存量记忆整体失效（`R56`）。回填后两表 audience 空值均为 0。
- `subject` 存量仍是空（348/348），只能靠后台模型重跑才会补上，不做启发式伪造。

## 局限与下一步

- `text` 是「答案原文是否在 prompt 里」的确定性代理，不等于最终回答正确率；回答准确率见 `docs/benchmark-report.md`（当前版 0.800–0.925，中位 0.825）。
- 真实快照里 `knowledge_boundary=self` 为 0 张、保密卡仅 1 张；已补 60 条合成专项探针（`docs/disclosure-corpus-2026-10-29.md`）：非主人场合（群聊/直播/未绑定私聊）45 条敏感题零原文泄漏，旧核心 45/45 全泄漏，普通卡未误伤；主人私聊按新策略放开 15/15。
- `subject` / `speaker` 只对**新归档的卡**生效（线上旧卡仍为空，需要重新走过归档才会补上）。
  主体加成仍只在「已验证主人的私聊」可达，因为群聊的逐条说话人身份还没透传给中间件（P1-2）。
- 闸门与显著性在本语料无触发，不能证明有效；应补「低证据问句」专项集（无可召回记忆、只共享泛词）再测。
- 紧预算只测了 3.6k token 一档；线上若调小 `RP_MAX_TOKENS`，建议再扫 2k/4k/6k。
