## 2.1 修复：cross-encoder 重排（commit `561510f`）

诊断先于动手：用库里预计算向量直接点积，46 题向量 recall@4 = **0.565**，
只有 3 条掉出前 100；16 条落在第 **5~50** 名，GT 与 top-1 余弦差仅 0.02~0.06。
也就是说，候选已经"在身边"，缺的是精排，不是更多候选。

| 方案 | recall@4 | MRR@4 |
|---|---|---|
| 纯关键词 | 0.239 | 0.185 |
| 纯向量（修复前线上路径） | 0.565 | — |
| 纯向量 + 重排（池 20） | 0.696 | 0.607 |
| 线上融合 + 重排（池 20，仅 RRF 截断） | 0.652 | 0.553 |
| **线上融合 + 重排（向量池 ∪ 钩子）** | **0.696** | **0.607** |

三处关键修正：

1. **候选必须是「向量池 ∪ 钩子命中」**。只吃 RRF 截断后的前 20，关键词命中的
   错误卡会占名额，把向量第 5~20 名的正确卡挤出候选（0.652 的损失就来自这里）。
2. **重排分数映射到 1.4~3.8**。原映射 0.5~3.8，第 4 名相对分 <0.35，会被
   `RECALL_MIN_REL` 当成噪音二次丢弃——语义已排好序，不该再用字面尺度过滤。
3. **重排单独 4 秒超时**（`RP_RERANK_TIMEOUT`）。它挂在每轮 prompt 构建的同步路径上，
   沿用 embedding 的 15 秒会把回复拖死；失败/无 key 时自动保持原序。

默认开启（`RP_RERANK=1`），可用 `RP_RERANK=0` 回滚；池大小 `RP_RERANK_POOL` 默认 20
（实测 20 与 50 同为 0.696）。46 题全部重测，回归 41 用例与示例断言全绿。

`inject` 仍为 0.587：差额主要来自人工 snippet 与卡正文措辞不同
（如标注"纠正称呼为蓝鲸"，卡写"澄清那是图名而非自己名字"），不是注入链路丢卡。

## 2.2 多路召回：摘要正文 / 词条 / 全量标签

重排只能排序、不能补候选。诊断显示 35 条失败里只有 3 条真正掉出向量前 100，
但关键词通道一直只看 `entity_hooks`，**97.8% 的标准答案所在的卡摘要正文从未进入词法索引**。
本轮新增三路纯词法候选，全部并入重排池：

| 通道 | 实现 | recall@4（单独） |
|---|---|---|
| 摘要正文 BM25 | 摘要 + hooks 建词项，BM25(k1=1.2, b=0.75) | **0.652** |
| 词条 BM25 | `durable_facts` 按 `turn_end` 映射回事件卡 | 0.391 |
| 全量标签倒排 | 2109+ 标签 IDF 匹配，含长尾标签 | 0.152 |

| 组合 | recall@4 / 覆盖率 |
|---|---|
| 重排（修复后，旧候选池） | 0.696 |
| 重排 + 扩大词法候选（20/20/15/20） | 0.761 |
| **重排 + 第二证据加权（最终）** | **0.804**，MRR 0.643 |
| **候选覆盖** | **0.935**（重排截断 60） |
| 无 embedding 的纯词法加权降级 | **0.674**（MRR 0.491，para 0.850） |

- 最终 46 题真实复测：字面题 0.846、换说法（para）0.750，95% CI [0.668, 0.893]。
- 两段增益：候选扩容（摘要 12→20、词条 10→15、标签 12→20）+0.044；
  摘要 BM25 0.35 / 词条 BM25 0.15 的归一化「第二证据」加权再 +0.043。
  这一项只抬升同分附近的卡，不改变候选集合；设 0 即回滚。
- 三路合计固定开销约 **25 ms/轮**（1320 卡），可忽略；纯 Python，无额外依赖。
- 后台联想的标签表由"出现次数 top 60"改为"全量标签按问句相关性排序 + 高频补满"
  （`RP_ASSOC_TAG_MAX` 默认 120），长尾标签（"叫醒约定""尾鳍"）首次进入后台可见范围。
- **长线记忆**：`rhythm` 默认改为只加固、不降低；`--decay` 才启用旧的时间淡忘。

开关：`RP_SUMMARY_RECALL` / `RP_SUMMARY_LIMIT`、`RP_FACT_RECALL` / `RP_FACT_RECALL_LIMIT`、
`RP_TAG_RECALL` / `RP_TAG_LIMIT`、`RP_RERANK_BOOST_SUM` / `RP_RERANK_BOOST_FACT`、
`RP_ASSOC_TAG_MAX`、`RP_RHYTHM_DECAY`。

## 3.1 回答准确率提升到 0.804（2026-11-24 迭代）

同一批 46 题、同一裁判模型（`deepseek-v4.1-flash`）、同一线上库备份，逐轮结果：

| 轮次 | 改动 | 回答准确率 | recall@4 | 注入命中 |
|---|---|---|---|---|
| 基线 | 初版 | 0.565 | 0.804 | 0.587 |
| ① 裁判配对修复 | judge 按 `(q, gt)` 配对，避免同卡多问共用 snippet | 0.674 | 0.804 | 0.587 |
| ② 词条证据块 | 新增【本轮证据·优先引用】：词条 BM25 + 卡片最贴句 | 0.739 | 0.804 | 0.717 |
| ③ 注入配额 4→5 + 钩子后置 | 重排前 4 张不再被泛词钩子卡挤掉 | 0.739 | 0.804 | 0.717 |
| ④ 人设对齐 + 证据认定 | 评测改用生产 `persona.py`；证据段计入【本轮记忆】 | **0.804** | **0.804** | **0.717** |

### 本轮代码改动

1. **披露**（`disclosure.py`）：私聊、非 `self` 边界、非敏感卡直接全文，不再按相对分降成
   paraphrase/hint。修复"召回到了却只给暗示"。
2. **证据块**（`rp_skeleton.py`）：新增 `_best_sentence` +【本轮证据·优先引用】，
   放在全部系统段之后（裁剪优先级最高）：
   - 前 3 条来自 `durable_facts` 的 BM25 命中（具体到人/时间/数量）；
   - 其余来自本轮全文注入的卡，先挑与问句最贴近的一句，挑不出就整段截断，
     保证"已召回到的卡一定在最后一屏出现一次"。
3. **注入配额**：`RECALL_CAP_BASE` 4→5；钩子独有卡（未进重排结果）改为排在重排全序
   之后，避免泛词问句（"主人喜欢什么样的形象"）里含"主人"的无关卡把语义正确的
   第 4、5 张挤出去。
4. **重排超时**（`embedding.py`）：`RP_RERANK_TIMEOUT` 默认 4→8 s，减少高峰期
   重排 `TimeoutError` 导致的静默退回原序。
5. **评测保真度**（`tools/eval_memory.py`）：
   - 支持 `RP_EVAL_PERSONA` 指向生产 `persona.py`。**这是本轮最大的一处失真修正**：
     旧评测用示例人设"沈青梧（伞铺）"去回答瑾瑜的记忆题，模型只能以第三人称
     "瑾瑜那边没存到原话"作答，系统性压低了准确率；换成生产人设后同一批回答
     准确率从 0.739 升到 0.804。
   - 回答留存上限 120→800 字、`max_tokens` 200→400，避免把带细节的长回答截断后误判。

### 剩余 9 条失败归因

| 类型 | 题 | 说明 |
|---|---|---|
| GT 过期/能力已变 | B站验证码、能否看图、现在几点 | 标准答案是旧能力/旧时刻，角色现在已能看图、能报时 |
| GT 自相矛盾 | 灰发绿瞳是谁、笨蛋表情包 | 卡片正文写"认出七濑胡桃后被否认"，裁判按"就是七濑胡桃"判 |
| 裁判要求超出 GT | 认错大肥鱼 | 裁判要求答"必应图片搜索"，但 GT 卡正文并无此词 |
| 真召回/表述缺口 | 两个角色、大肥鱼表情包、午饭几碗、agent/MCP | 同类事件多、问法不带实体名，或时间冲突 |

4 条"GT 过期/矛盾/裁判越界"属于评测集质量问题，不改代码；其余 4 条是
"同类多次事件 + 问句不带实体"的固有难点，继续提升需要事件卡去重合并或
问句侧实体扩展。
